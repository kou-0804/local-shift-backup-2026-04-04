# 勤務表作成ツール 開発ガイド（完全未経験者向け）

このガイドは、**プログラミングをやったことがない人**が、AI開発支援ツール「Claude Code」を相棒にして、
自分の病院用のシフト（勤務表）自動作成ツールを完成させるための手順書です。

- 出発点：すでに動いている既存ツール（Python製・最適化エンジン搭載）を**雛形**にします
- 進め方：**コードを自分で全部書くのではなく、Claude Codeに作らせて、あなたは「確認」する**
- ゴール：自分の病院の設定を入れて、**ボタンを押すとExcelの勤務表が出てくる**ツール

> 💡 **このガイドの使い方**
> 上から順に進めてください。「▶ Claude Codeに送る文」と書いてある枠は、**そのままコピーして貼り付ける**ための指示文です。
> 専門用語は§0の「用語ミニ辞典」で説明しています。分からない言葉が出たら戻って確認してください。

## §0 全体像とゴール

### このツールができること
- 各部署（MRI・CT・夜勤など）に**必要な人数とスキル**を満たすように、職員を自動で割り当てる
- 公休（休み）の日数、夜勤の回数、有給などの希望を考慮する
- 結果をExcelの勤務表として出力する

### なぜ「自分で全部作る」のではないのか
シフト作成の心臓部は「**数理最適化**」という難しい技術（OR-Tools / CP-SATソルバー）でできています。
ここを未経験から自作するのは現実的ではありません。そこで、**すでに完成している既存ツールの心臓部はそのまま使い**、
あなたの病院に合わせて「設定」と「見た目」だけを変えていきます。

### 所要時間の目安（未経験者の場合）
| 工程 | 目安 |
|---|---|
| §1〜§3（準備とClaude Code入門） | 半日〜1日 |
| §4〜§5（要件整理と設定の書き換え） | 1〜3日 |
| §6（固有ロジックの外出し＝一番の山） | 3日〜2週間 |
| §7〜§8（GUIと検証） | 2〜5日 |
| 合計 | **おおむね2〜4週間**（毎日少しずつでOK） |

> ⚠️ **正直な注意点**
> §6が最大の難所です。既存ツールには「この病院だけのルール」（特定の機器のスキル要件、特定職員の特別ルール等）が
> プログラムの中に直接埋め込まれています。これを「設定ファイル」に追い出す作業が一番時間がかかります。
> ただし**そこもClaude Codeに任せられます**。あなたの仕事は「指示する」と「出てきた勤務表が正しいか確認する」ことです。

## §1 準備（インストール）

ツールを動かすために、PCに4つの道具を入れます。**ターミナルにコマンドを1行ずつコピペ**して実行してください。
（コマンドを貼り付けたら最後に Enter キーを押します）

### 1-1. ターミナルを開く
- **Mac**：`command + スペース` →「ターミナル」と入力して開く
- **Windows**：スタートメニューで「PowerShell」と入力して開く

### 1-2. Python を入れる
ツール本体を動かす言語です。

**Mac**（先に Homebrew というインストーラを入れます）
```bash
# Homebrew（まだ無ければ）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
# Python
brew install python@3.12
```

**Windows**
1. https://www.python.org/downloads/ を開く
2. 「Download Python 3.12.x」を押してインストーラを実行
3. ⚠️**最初の画面で「Add python.exe to PATH」に必ずチェック**を入れてから「Install Now」

確認（両OS共通。バージョン番号が出ればOK）：
```bash
python3 --version
```
> Windowsで `python3` が無いと言われたら `python --version` を試してください。

### 1-3. VS Code を入れる（コードを見る・編集する画面）
https://code.visualstudio.com/ からダウンロードしてインストール。
ファイルの中身を見たいときに使います（無くてもClaude Codeだけで進められますが、あると安心）。

### 1-4. Claude Code を入れる（AIアシスタント本体）
最新の入れ方は公式サイトが確実です：**https://docs.claude.com/claude-code**
（多くの場合、ターミナルで次の1行）
```bash
curl -fsSL https://claude.ai/install.sh | bash
```
インストール後、ログインします：
```bash
claude
```
初回はブラウザが開いてログインを求められます。指示に従ってください。

### 1-5. ツールに必要な部品（依存関係）を入れる
これは§2でツールを入手した**後**に行います（場所を§2-3で説明）。先に名前だけ知っておけばOK：
`ortools`（心臓部）、`pandas`（表の処理）、`openpyxl`（Excel出力）、`streamlit`（画面）。

> 🆘 **うまくいかないとき**
> エラーが出たら、**そのエラー文をまるごとコピーしてClaude Codeに貼り付け**、「この環境構築のエラーを直して」と頼めば解決を手伝ってくれます。

## §2 ベース（雛形）を入手する

既存ツールを「自分用のコピー」として手元に持ってきます。

### 2-1. 作業フォルダを作る
```bash
cd ~/Desktop
mkdir shift-tool
cd shift-tool
```

### 2-2. 既存ツールのファイルを置く
既存ツールのフォルダ一式（`shift_scheduler/` や設定CSVなど）を、この `shift-tool` フォルダにコピーします。
- 友人（このガイドを渡した人）から**ZIPでもらう**か、GitHubのリポジトリを教えてもらってください。
- GitHubから取る場合（URLは実際のものに置き換え）：
```bash
git clone https://github.com/＜教わったURL＞.git .
```

### 2-3. 依存関係を入れる
ツールのフォルダの中で（`requirements.txt` があればそれを使うのが確実）：
```bash
# 仮想環境（このツール専用の部品置き場）を作る
python3 -m venv venv
# 有効化：Mac
source venv/bin/activate
# 有効化：Windows（PowerShell）
venv\Scripts\Activate.ps1

# 部品をインストール
pip install ortools pandas openpyxl streamlit
# もし requirements.txt があるなら代わりに：
# pip install -r requirements.txt
```
> 💡 `venv` を有効化すると行頭に `(venv)` と出ます。**ターミナルを開き直すたびに有効化が必要**です。

### 2-4. 自分用のバックアップ先（GitHub）を用意する
最初に「セーブできる場所」を作っておくと安心です。
1. https://github.com で無料アカウントを作る
2. 緑の「New」ボタンで空のリポジトリを作る（例：`my-hospital-shift`）
3. ここから先は、迷ったらClaude Codeに丸投げできます：

> ▶ **Claude Codeに送る文**
> 「このフォルダをGitで管理して、私のGitHubリポジトリ `https://github.com/＜あなたのID＞/my-hospital-shift.git` に
> 最初のコミットをプッシュしたいです。手順を1つずつ実行してください。途中で私がやることがあれば教えてください。」

## §3 Claude Codeの基本

Claude Code は、ツールのフォルダの中でターミナルから `claude` と打つと起動します。
あなたが日本語でお願いすると、ファイルを読んだり、書き換えたり、コマンドを実行したりしてくれます。

### 3-1. 安全に進める3原則
1. **小さく頼む**：一度に大改造を頼まない。「まず○○だけして」と1歩ずつ。
2. **こまめにセーブ（コミット）**：うまくいったら必ず記録。壊れても戻せます。
   > ▶ 「ここまでの変更をコミットして、メッセージは日本語で分かりやすくして」
3. **分からなければ説明させる**：「なぜそうしたのか初心者にも分かるように説明して」と必ず聞く。

### 3-2. 困った時の「聞き方テンプレ」
そのままコピーして、`＜＞`の中身だけ自分の状況に変えて使ってください。

> ▶ **エラーが出た時**
> 「次のエラーが出ました。原因を初心者にも分かるように説明してから、直してください。
> 直したあとは、本当に直ったか実際に動かして確認してください。
> エラー：
> ```
> ＜エラー文をまるごと貼る＞
> ```」

> ▶ **やりたいことを伝える時**
> 「＜やりたいこと＞をしたいです。まず何をするか手順を説明してから、1つずつ進めてください。
> 私の確認が必要なところでは止まって聞いてください。」

> ▶ **不安な変更を頼む時**
> 「変更の前に、今の状態をコミットしてセーブしてください。そのあとで＜変更内容＞をしてください。
> もし結果が悪ければ元に戻せるようにしておいてください。」

### 3-3. やってはいけないこと
- ❌ 出てきたコードを**確認せず**にどんどん進める（後で何が起きたか分からなくなる）
- ❌ セーブ（コミット）せずに大量に変更する
- ✅ 代わりに：1機能できたら動かして確認 → コミット → 次へ、を繰り返す

下の表を**友人に記入してもらって**ください。これが設定ファイルの設計図になります。

### シート①：勤務場所（部署）と必要人数
曜日ごとに「何人必要か」を書きます。

| 場所名 | 区分 | 月 | 火 | 水 | 木 | 金 | 土 | 日 | 性別の制約 |
|---|---|---|---|---|---|---|---|---|---|
| 例）病院MRI | MRI | 3 | 3 | 3 | 3 | 3 | 2 | 0 | なし |
| 例）マンモグラフィ | 検査 | 1 | 1 | 1 | 1 | 1 | 1 | 0 | 女性のみ |
| （以下、部署の数だけ追加） | | | | | | | | | |

### シート②：スキル（誰が何をできるか）
場所ごとに「できる人」のレベルを管理します。レベルは例として A=ベテラン / B=一人前 / C=見習い / D=未経験 のように決めます。

| 職員名 | 経験年数 | 病院MRI | CT | 夜勤 | … |
|---|---|---|---|---|---|
| 例）田中 | 10 | A | B | ○ | |
| 例）佐藤 | 2 | C | B | × | |

### シート③：各場所の人員構成ルール（任意）
「この部署はAランクが最低1人必要」「見習いだけにしない」等のルールがあれば。

| 場所 | 最低ランク | 最低人数 | 備考 |
|---|---|---|---|
| 例）病院MRI | A | 1 | A以上が1人は必須 |

- 1か月の夜勤の総回数、1人あたりの上限：
- 月ごとの公休（休み）日数：
- 夜勤の翌日は必ず休み（明け休み）か：はい / いいえ
- 連続勤務の上限日数：

### シート⑤：特別ルール（あれば）
「この職員は管理職なので現場に入らない」「この機器は特定の資格者だけ」等、自由記入。

> 💡 記入に迷ったら、既存ツールの設定ファイル（§5で見ます）を「お手本」として友人に見せると、何を書けばよいか伝わります。

## §5 設定を自分の病院仕様にする

既存ツールの設定は `data/` フォルダの中のCSVファイル群です（Excelで開けます）。
代表的なファイル：
- 勤務場所マスタ … 部署と必要人数（シート①に対応）
- スキルマスタ … 誰が何をできるか（シート②）
- 技師マスタ … 職員一覧（名前・経験年数・夜勤可否）
- 公休数マスタ … 月ごとの休み日数（シート④）
- 夜勤回数 … 夜勤の割り当て回数（シート④）

### 進め方
まずClaude Codeに「全体像」を説明してもらいます。

> ▶ **Claude Codeに送る文（まず構造を理解する）**
> 「`data/` フォルダの中の各CSVファイルが、それぞれ何を表しているのかを、初心者向けに一覧で説明してください。
> 列の意味も簡単に教えてください。実際にファイルを書き換えるのはまだしないでください。」

次に、§4で集めた友人の病院の情報に置き換えます。

> ▶ **Claude Codeに送る文（置き換え）**
> 「友人の病院の情報を渡します。これに合わせて `data/` のCSVを書き換えてください。
> 1ファイルずつ進め、書き換えたら内容を表で見せて、私の確認を取ってから次に進んでください。
> ＜ここにシート①〜⑤の内容を貼り付け＞」

> 💡 列の構成自体を変える必要が出るかもしれません（例：部署が全然違う）。その場合もClaude Codeが調整します。
> 「列が足りない／余る場合は、どう直すか提案してから直して」と添えると安全です。

### この章のゴール
- `data/` のCSVが友人の病院の内容になっている
- ここで一度**コミット**（▶「ここまでをコミットして」）

## §6 固有ロジックの外出し（最大の山）

ここが一番の難所です。CSVを変えただけでは直りきらない「**プログラムの中に直接書かれた、元の病院だけのルール**」が残っています。
（例：特定の機器のランク要件が曜日で変わる、特定職員だけの特別扱い、等）
これらを見つけ出し、**CSV等の設定ファイルから変えられる形**に作り替えます。

### 6-1. まず「埋め込みルールの棚卸し」をさせる
いきなり直さず、**どこに何が埋まっているか一覧**を作るのが先です。

> ▶ **Claude Codeに送る文（棚卸し）**
> 「このツールの中に、特定の病院だけに当てはまる『ハードコードされたルール』（プログラム内に直接書かれた数値や固有名詞、
> 特定の場所・職員に限定した条件）がどこにあるか、すべて洗い出してください。
> ファイル名・行・どんなルールか・なぜ病院固有と判断したか、を表にまとめてください。
> この段階では修正はせず、一覧だけ作ってください。」

出てきた一覧を友人と見て、「これは残す／これは変えたい」を仕分けします。

### 6-2. 1つずつ設定ファイルへ追い出す
**一度に全部やらない**こと。1ルールずつ、外出し → 動かして確認 → コミット、を繰り返します。

> ▶ **Claude Codeに送る文（1つずつ外出し）**
> 「棚卸し表の『＜対象ルール名＞』を、プログラムに直接書くのをやめて、設定ファイル（CSVかYAML）から
> 読み込む形に変えてください。手順は次の通り：
> 1) どう変えるかを先に説明する
> 2) 変更前に現状をコミットしておく
> 3) 変更する
> 4) サンプル設定で実際に勤務表を作り、変更前と結果が変わっていないことを確認する
> 5) 問題なければ結果を私に見せる
> 途中で判断が必要なら止まって聞いてください。」

### 6-3. 「結果が変わっていないか」の確認が命
外出しは「**動きは同じまま、設定で変えられるようにする**」のが目的です。
変更のたびに、同じ条件で勤務表を作って**前と同じ結果か**を必ず確認します。

> ▶ **Claude Codeに送る文（検証）**
> 「今の変更で、勤務表の中身が変わっていないことを確認したいです。
> 変更前と変更後で同じ入力から勤務表を作り、違いがあれば具体的に教えてください。違いが無ければ『一致』と教えてください。」

> ⚠️ ここは焦らないこと。1日1〜2ルールずつでも構いません。**確実に動く状態をコミットで積み上げる**のが結局一番速いです。

### この章のゴール
- 病院固有のルールが、プログラムではなく**設定ファイル**で変えられる状態になっている
- 友人の病院のルールに設定し直して、**現実的な勤務表が出る**

## §7 簡易GUIを載せる

ターミナルでコマンドを打つ代わりに、**画面のボタンで実行**できるようにします。Streamlit を使います。

> ▶ **Claude Codeに送る文（GUI作成）**
> 「Streamlit を使って、このツールの簡単な操作画面（app.py）を作ってください。必要な機能：
> 1) 対象の年月を選ぶ
> 2) 設定ファイル（dataフォルダ）の場所を選ぶ、または現在の設定を使う
> 3) 『勤務表を作成』ボタンを押すと処理が走り、進み具合が分かる
> 4) 完成したら Excel ファイルをダウンロードするボタンが出る
> 5) エラーが起きたら、初心者にも分かるメッセージを画面に出す
> まず画面の構成を説明してから作り、作ったあと起動方法を教えてください。」

起動方法（作成後）：
```bash
source venv/bin/activate          # Macの場合（Windowsは venv\Scripts\Activate.ps1）
streamlit run app.py
```
ブラウザが自動で開きます。開かなければ、ターミナルに出る `http://localhost:8501` をブラウザに貼り付けます。

> 💡 ボタンを押しても何も起きない／エラーが出る場合は、§3-2の「エラーが出た時」テンプレで、画面とターミナルの
> エラー文をまるごとClaude Codeに渡してください。

### この章のゴール
- ブラウザで、年月を選んでボタンを押すと、Excelの勤務表がダウンロードできる

## §8 動かす・検証する

「動いた」だけでは不十分で、「**勤務表として正しいか**」を友人にチェックしてもらうのが大事です。

### 8-1. 出力Excelの確認ポイント（友人にお願いする）
- [ ] 各部署が、必要な人数を満たしているか
- [ ] スキルの無い人が、できない部署に入っていないか
- [ ] 公休（休み）の日数が、人ごとに正しいか
- [ ] 夜勤の翌日が休み（明け）になっているか
- [ ] 特定の人に偏りすぎていないか

### 8-2. よくあるエラーと対処
| 症状 | だいたいの原因 | 対処 |
|---|---|---|
| `ModuleNotFoundError` | 部品が入っていない／venv未有効化 | `source venv/bin/activate` の後 `pip install ＜名前＞` |
| 文字化け（CSV） | 文字コードの違い | Claude Codeに「CSVの文字コードをUTF-8で統一して」 |
| 「解が見つからない(infeasible)」 | 条件が厳しすぎて全部は満たせない | Claude Codeに「どの制約が原因か調べて、緩められる候補を教えて」 |
| 結果が毎回変わる | 計算のばらつき | Claude Codeに「結果が毎回同じになるよう固定して」 |

> ▶ **どんなエラーでも使える万能テンプレ**
> 「次の問題が起きています。初心者にも分かるよう原因を説明し、直してから、実際に動かして直ったことを確認してください。
> ＜画面やターミナルのエラーを貼る＞」

### 8-3. 「正しさ」をテストで守る（任意・推奨）
一度正しく動いたら、それを**自動チェック**として残せます。

> ▶ 「今の正しい結果を基準にした自動テストを作ってください。今後変更したときに、勤務表が壊れていないか
> 自動で確認できるようにしたいです。テストの動かし方も教えてください。」

## §9 運用（毎月の使い方・バックアップ）

### 9-1. 毎月の使い方
1. ターミナルでツールのフォルダに移動し、venvを有効化
2. `streamlit run app.py`
3. 画面で対象の年月を選ぶ
4. その月の希望休などがあれば設定ファイルを更新（または画面から入力）
5. 「勤務表を作成」→ Excelをダウンロード
6. 内容を確認して微調整

### 9-2. 設定を変えたくなったら
- 部署・人数・スキル・職員の増減 → `data/` のCSVを編集（Excelで開ける）
- ルールそのものの変更 → Claude Codeに「＜変えたいルール＞を変更したい」と相談

### 9-3. バックアップ（必ず習慣に）
変更したら**こまめにGitHubへプッシュ**します。これをやっておけばPCが壊れても安心です。

> ▶ **Claude Codeに送る文**
> 「ここまでの変更をコミットして、GitHubにプッシュしてバックアップしてください。コミットメッセージは日本語で分かりやすく。」

手で行う場合（基本の3コマンド）：
```bash
git add -A
git commit -m "今日の変更内容を書く"
git push
```

## 🎯 まとめ：迷ったらこの3つ
1. **1歩ずつ**（一度に大改造しない）
2. **動いたらコミット＆プッシュ**（セーブとバックアップ）
3. **困ったらエラーをまるごとClaude Codeへ**（§3-2／§8-2のテンプレ）

このツールの心臓部（最適化）は完成品を使うので、あなたの役目は
「**何が欲しいかを伝える**」「**出てきた勤務表を確認する**」の2つです。焦らず、少しずつ進めてください。

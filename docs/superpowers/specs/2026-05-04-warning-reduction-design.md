## 背景・問題の診断

### 現在の警告内訳（32件）

| 場所 | 件数 | 内容 |
|------|------|------|

| 夜勤HB | 2件 | 夜勤チームにHB対応者なし（5/9, 5/23） |

### 根本原因

CP-SAT ソルバーは以下の2つのペナルティを使って配置を最適化している:

1. **パワーバランス違反ペナルティ: 3,000,000点/件**（病CT・CLMRのA/Bランク要件等）
2. **場所不足ペナルティ: 100,000点/人**（全場所一律）

この**30倍の重み差**により、ソルバーは病CT・CLMRのランク要件を満たすことを最優先し、  
CT・病院MR の人数充足が犠牲になる。

```
デバッグ結果 (5/12):
CT有資格=32名(A/B:22名) が available だが CT=1人のみ配置
残り19名: 病CT→6, ク→5, CLMR→4, ア→2, ポ→2
```

また、プリシーダーの安全バッファが `req+1` と浅いため、  
重要場所の資格者が特定の日に休み集中しやすく、ソルバーの選択肢が狭まっている。

---

## 設計（複合アプローチC）

### Fix 1: プリシーダー安全バッファの強化

**対象ファイル:** `main.py` の `pre_seed_rest_days()` → `_would_exceed_skill_capacity()`

**変更内容:**

```python
# 現状（全場所一律）
threshold = req_count + 1

# 変更後（重要場所に大きなバッファ）
CRITICAL_BUFFER = {
    '病CT':  4,   # req=6 → threshold=10
    'CT':    3,   # req=4 → threshold=7
    '病院MR': 3,  # req=3 → threshold=6
    'CLMR':  2,   # req=4 → threshold=6
    'MG':    2,   # req=1 → threshold=3
}
threshold = req_count + CRITICAL_BUFFER.get(loc.code, 1)
```

**期待効果:** 重要場所の資格者が同じ日に休み集中するのを防ぎ、  
ソルバーが使える候補数を増やす。

**制約:** プリシーダーは各スタッフの 10日公休目標を守る。  
バッファを大きくすることで一部スタッフの休み候補日が減る可能性があるが、  
十分な候補日数が確保できる場合のみ適用する（既存の `if not candidates: continue` で保護済み）。

---

### Fix 2: 場所別不足ペナルティの調整

**対象ファイル:** `shift_scheduler/src/schedulers/day_scheduler.py` の `_schedule_one_day()`

**変更内容（DH-03 セクション）:**

```python
# 現状
DEFICIT_PENALTY = 100000

# 変更後
DEFICIT_PENALTIES = {
    'CT':    200000,  # 2倍: ポ/ク への副作用を最小化しつつ効果を出す水準
    'MG':    150000,  # 1人場所は少し強調（完全未配置を防ぐ）
    'OP':    150000,
    '超遅':  150000,
}
DEFICIT_PENALTY_DEFAULT = 100000
penalty = DEFICIT_PENALTIES.get(loc.code, DEFICIT_PENALTY_DEFAULT)
```

**理由:**
- 試験結果: 1.5M〜2M に引き上げるとCTは埋まるがポ/ク が犠牲（警告増）
- 2倍（200K）は副作用が最小限になる見込みの水準
- 病CT・病院MR は3Mのパワーバランス制約に守られており、追加ペナルティ不要

---

### Fix 3: 夜勤HBカバレッジ改善

**対象ファイル:** `shift_scheduler/src/schedulers/night_scheduler.py`

**現状:** 5/9・5/23 に夜勤チームにHB対応者がいない（2件の警告）

**変更内容:** 夜勤アサイン時にHBスキル保有者（Aランク）が少なくとも1名  
含まれるようにするソフト制約を追加（または既存制約の重みを調整）。

**スコープ注記:** Fix 1・2 の実装後に残る警告数を見て判断する。  
効果が小さければスキップ可。

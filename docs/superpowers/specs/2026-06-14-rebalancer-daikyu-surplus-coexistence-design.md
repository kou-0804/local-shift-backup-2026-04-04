# 代休×余剰公休の併存解消 — リバランサー強化 設計

- 日付: 2026-06-14
- 対象ファイル: `main.py` `rebalance_workload()`（後段グリーディ・リバランサー, commit 0610b76 起点）
- 方式: 案A（既存リバランサーの増分強化）

## 1. 背景と問題

担当者の手直し時間短縮が最上位ゴール。日勤生成後に `rebalance_workload()` が
過剰休（公休>目標）の人の空き平日へ日勤を移し、代休（公休<目標）の人を休ませて
全員を目標公休に寄せている。

7月実データの精査で、当初メモの前提「夜勤者約17名が構造的に余剰公休を蓄積」は
**誤読**と判明した。公休=31（全休）の17名は本スケジューラの管轄外:

- **別部門**: 核医学（小出・畠山・池田・植野・氏家）／治療（高重・苅込・里見・佐藤正哉・荒井・今溝・垂水）
- **長期休/育休**: 大島（育休開始, 当月ほぼ全休=原田と同じ扱い）／原田（当月全休）
- **新人(1年目)**: 野本・折見・海野
- **MRI専門**: 矢野

これらを除いた**真の画像診断ローテ要員**の余剰はほぼ均等で、是正対象は小さい:

| 区分 | 人数 | 余剰(公休−目標9) |
|---|---|---|
| 須田 章則 | 1 | +2 |
| 河西・箕輪・佐藤海夢・星・谷 | 5 | +1 |
| 加藤義明(MRI専門)・森 | 2 | +0.5 |
| 代休(松井・田﨑) | 2 | −0.5 |

7月の代休は **1.0日（松井0.5 + 田﨑0.5、両名とも女性・ク中心）** のみ。
両名の代休は (a) 女性ク有資格の余剰者が河西1名のみ (b) 河西の空き平日(7/20月)が
松井/田﨑の移動可能ク日と噛み合わない (c) 不足が**半休(0.5)**で現リバランサーの
整数日移動では届かない、という三重苦で残存している。

## 2. ゴール（受け入れ基準）

ユーザー方針:
> 代休が発生している人がいる状態で、同時に余剰公休（有休）を生んでいるのが問題。
> 代休が残る限り余剰を遊ばせず代休解消に回す。休みの配置では連勤に十分留意する。

受け入れ基準:

1. **代休×余剰の併存最小化**: 代休（公休<目標）が1人でも残る限り、ローテ要員の
   余剰公休（公休>目標）を代休解消へ回す。代休が0になれば残余の余剰は許容。
2. **連勤厳守**: 移動の結果、誰も連勤6日を超えない。休みの配置が極端に偏らない。
3. **非劣化**: 既存の全個別ルール遵守・人員不足警告0・決定性（同一入力→同一出力）を維持。
4. **正直性**: 構造的に代休を0にできない場合、「なぜ不可能か」をログで明示する
   （改善できないのに「完了」と言わない）。

非ゴール（YAGNI）:
- 余剰公休の厳密な分散最小化（当初メモの大型案件）は実体が無いため対象外。
- CP-SAT 大域最適化（案B）は過去に複数回 INFEASIBLE/非決定で revert 済み、対象外。
- 別部門・育休・新人・MRI専門の扱いは現状維持（触らない）。

## 3. 設計

`rebalance_workload()` への増分変更（4点）。既存の決定的グリーディ構造を維持する。

### 3.1 スコープ衛生 `_in_rotation(sid, month)`

別部門・長期休者が巨大 over として誤ターゲットにならないよう、**over集合・mover から除外**する判定を追加。

- 除外条件:
  - 備考 ∈ {`核医学`, `治療`}（別部門）
  - 当月ほぼ全休（育休/長期休）: 当月の実勤務日数がごく僅か（☆育/★ の長期連続申請）
    → ローテ外とみなす。判定はしきい値ベース（例: 実勤務日数が一定未満、または
    `公休 >= 当月日数 − k`）。大島・原田が該当。
  - 新人(経験年数==1)・MRI専門（既存方針「触らない」）
- 効果: これらは「余剰」と数えない（見かけ値を排除）。recipient 候補からも外れる。
- 注意: 加藤義明(MRI専門)は実ローテで MRI を担うが、公平化対象外の既存方針を踏襲し
  mover/recipient からは除外（余剰+0.5 は放置で可）。

### 3.2 代休最優先ループ

- 代休（rest < target）が1人でも残る限りループ継続。余剰者→代休者の肩代わりを最優先。
- **最後の代休を消すための許容**: 全日移動で under が target を 0.5 超過する場合でも、
  その移動で**代休総量が減る**なら実行可（代休0なら残余余剰は許容、という基準に整合）。
- 既存の 1対1 移動 + 2-hop 玉突き（recipient を別 over へ退避して空き平日を作る）を維持。

### 3.3 半休(0.5)対応

- `rest_count` は既に半休（出/☆=0.5）を分数で数えている。移動判定側も 0.5 単位を
  扱えるようにする。
- 0.5 代休の解消手段:
  - mover U が**半日要素**（`17休`/`出/☆` 等）を持つ日を 0.5 単位で調整、または
  - U の全日勤務 L(d) を recipient O へ移し U を半休/全休化して 0.5 不足を解消。
- 過剰移動（0.5不足に対し1.0付与で +0.5 余剰化）は、3.2 の許容範囲（代休が減るなら可）。

### 3.4 連勤の厳格化（休み配置の質）

- recipient O: 移動後 `consec_if_work(O,d) <= 6`（既存維持）。
- mover U: 付与した休みが連勤を適切に分断しているか評価。最低限、移動が
  どこかの連勤6超を新たに作らないことを保証。可能なら孤立配置（飛び石の極端な偏り）を避ける。

## 4. 検証計画

1. **7月再生成**: 既存実行手順で `output/勤務表_2026年7月.xlsx` を再生成。
   before/after で「代休×余剰の併存」を実測。
2. **正直な結果報告**: 7月の代休1.0日が消せた/消せない を明示。消せない場合は
   女性ク有資格者の枯渇という構造的理由をログ出力。
3. **回帰**: 6月（代休3.0日）で再実行し、代休非劣化・警告0・全個別ルール遵守・
   決定性（同一入力で複数回 MD5 一致）を確認。
4. **検証ツール**: `scratch/verify_schedule.py`（個別ルール/代休/場所別の幅）、
   `scratch/fairness_report.py`（保護除外の精密ばらつき）。

## 5. リスクと留意

- **構造的下限**: 7月の代休1.0日は女性ク枠の構造的ボトルネックで0にできない可能性が高い。
  その場合の成果は「不可能であることの明示」。過剰な最適化で他ルールを壊さないこと。
- **決定性の維持**: set 反復順・乱数に依存する変更を入れない。グリーディは確定順序を保つ。
- **半休ロジックの複雑性**: 0.5 単位は最終公休カウント（assign_monthly_off_days）と
  整合させる。`出/☆=0.5`・`17休単独=休/17休+日勤=勤務` の既存基準を厳守。
- **スコープ判定の堅牢性**: `_in_rotation` のしきい値は実データ（核医学/治療/育休/新人）で
  誤判定が出ないことを確認。
